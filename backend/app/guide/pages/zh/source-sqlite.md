# SQLite

你个人存储中的一个 SQLite 数据库文件。你可以浏览它的表和视图，按页读取和编辑它们的行，查看表的结构，阅读文件为表保存的 DDL，并在控制台中运行 SQL。连接的一般用法见 [连接](connections.md) 页面。

## 你可以看到的内容

- 表、视图和虚拟表，以及排序和筛选后的行
- 表的列、键、检查和索引，以及它引用的表
- 关系的 DDL，即文件保存的样子，连同其索引和触发器
- 你编写的 SQL 的结果，以及 SQLite 对查询的执行计划
- 所有匹配的行，下载为文件
- 文件对自身的说明：布局、完整性、损坏的键、触发器，以及此服务器的 SQLite 提供的功能
- 一行的外键通向哪里，以及什么指向它

## 你可以更改的内容

- 表数据：编辑单元格、粘贴块、插入和删除行
- 列、索引、唯一键和外键
- 新表，逐个对象设计或由行创建
- 表和视图：重命名、删除
- 连同结构复制的表，复制到另一个 SQLite 文件或本文件
- 整个文件的备份与恢复
- 通过控制台中的 SQL 修改数据和结构

## 连接

窗口的 **连接** 页面要求填写：

- **数据库文件**：文件在你个人存储中的路径，例如 `data/shop.db`。请先通过 **文件** 连接把文件放到那里。存储之外的路径会被拒绝。
- **文件不存在时创建**：勾选它可以从一个空数据库开始。不勾选时，不存在的文件无法通过检查，这样输错的路径不会留下一个空文件。文件夹必须已经存在。

你已经在 **文件** 连接中看到的数据库文件可以直接从那里连接：**作为 SQLite 连接** 会替你填好此窗口。

每次请求都会重新打开文件，因此通过 **文件** 替换的文件会按它现在的样子读取。

无论文件里有什么，连接到该文件都无法做到：打开第二个文件（`ATTACH`、`VACUUM INTO`）、加载扩展，或访问服务器上的任何其他内容。任何人都可以上传文件，因此其中的视图或触发器也无法调用有副作用的函数。

## 目录

- 第一层是 `main`，即文件唯一的模式。
- 其中是它的表、视图和虚拟表。点击其中一个会在标签页中打开它的行。
- SQLite 自己的表（`sqlite_schema`、`sqlite_sequence`、`sqlite_stat1`）以及虚拟表为自身保存的表（例如全文索引的表）会被标记为系统表。
- 只有在对文件运行 `ANALYZE` 之后，表才会给出大致的行数。不会有任何东西去统计行数。
- **详情** 显示一个关系有多少列、索引和约束。
- **查看 DDL** 显示文件保存的 `CREATE TABLE` 或 `CREATE VIEW` 语句，后面跟着表的索引和触发器。
- 使用此服务器没有的模块创建的虚拟表会被列出，并在打开时说明这一点。
- `main` 之后的 **系统** 是一个报告分区（见下文 **报告**）。
- 页眉中的搜索按名称以及按列查找表和视图。

## 读取行

表以网格打开，每次一页，排序和筛选方式与 PostgreSQL 表相同。每一列都可以排序。一列提供哪些筛选取决于它声明的类型：数字、日期和文本可以比较；文本可以按包含和开头匹配；每一列都可以按为空或不为空筛选。

- 分页按主键，否则按行写入的顺序（`rowid`）。视图按 SQLite 返回的顺序排列。
- 在文本筛选中输入的 `%` 或 `_` 按其本身查找。文本筛选不区分拉丁字母的大小写。
- 没有声明类型的列按文本筛选。

值的显示方式：

- 值按它实际的样子显示，无论它的列怎么说：SQLite 允许 `INTEGER` 列保存文本，文本就按文本显示；
- 任何列中的二进制值都以十六进制显示，例如 `0x00FF`；
- `BOOLEAN` 列在保存 0 或 1 的地方显示为 `true` 或 `false`；
- 不是有效 UTF-8 的文本以十六进制显示，而不是显示并不存在的字符；
- 大整数精确显示。

## 修改行

拥有 **编辑行** 权限时，表可以像 PostgreSQL 表一样在网格中编辑：双击单元格、粘贴块、**插入行**、勾选行并 **删除所选行**。视图、虚拟表和 SQLite 自己的表是只读的，生成列是计算出来的，而不是写入的。

- 通过主键重新找到一行；表没有主键时通过它的 `rowid`。
- 如果在你读取之后有人修改了这一行（无论哪一列），你的修改会被拒绝，而不会覆盖对方的修改。请重新加载后再试。
- 按网格显示的方式写入值：在 `BLOB` 列中把二进制写成 `0x…`，在 `BOOLEAN` 列中写 `true` 或 `false`。没有类型的列会让数字保持为数字。其他列收到的值，SQLite 会按其类型转换后保存。
- `STRICT` 表会在写入任何内容之前拒绝类型错误的值，并指出保存这些值的单元格。粘贴的块要么全部写入，要么一点也不写入。
- 表的键、检查或必填列拒绝的修改不会执行，并会说明是哪条规则拒绝的。文件的外键会被强制执行。
- 外键中的单元格带有一个箭头，可以打开它指向的行；**指向此行的是什么** 会打开指向这里的行。

## 更改结构

表的 **结构** 会像修改 PostgreSQL 表那样修改它：添加、重命名和删除列，设置或移除默认值，要求或不再要求值，更改类型，添加和删除索引、唯一键和外键。

- SQLite 本身只能添加一个允许为空的列和重命名列。其他所有操作都按照 SQLite 文档描述的方式重建表：新建一张表，连同 `rowid` 复制行，替换旧表，重新创建它的索引和触发器。修改没有涉及的内容 —— `AUTOINCREMENT`、`DEFERRABLE`、注释 —— 都按原样保留。
- 与现有行相矛盾的修改不会执行，并会显示数量：没有值的行、重复的值、指向不存在内容的行。
- 在 SQLite 中，有类型的列可以接受任何值，因此只有在 `STRICT` 表中才会拒绝类型更改，并统计它无法保存的值。
- 删除一列会删除基于它的键和索引。读取该列的检查或视图会拒绝删除，并指出是哪一个。
- 提供的类型是 SQLite 的类型：文本、整数、浮点数、数值、布尔、日期、日期和时间、JSON、UUID 和二进制。`STRICT` 表提供它自己的类型：文本、整数、浮点数、二进制和任意值。
- SQLite 只构建一种索引，即 B 树，并按照表和列为它创建的对象命名。

## 创建表

`main` 操作菜单中的 **创建表** 会打开表设计器，与 PostgreSQL 相同。计划是一条 `CREATE TABLE` 加上每个索引一条 `CREATE INDEX`，一起执行：表要么完整创建，要么完全不创建。

- 标识列就是 SQLite 自己的行号：一个构成整个主键的整数，写作 `INTEGER PRIMARY KEY AUTOINCREMENT`。它可以从任意值开始，每次加一，并接受你写入的值。
- SQLite 没有的功能会在你审阅计划之前标记在提出要求的对象上：不记日志的表或分区表、在提交时检查的唯一键、空值排在最前或最后、索引附带的额外列。
- SQLite 拥有 MySQL 缺少的功能：部分行上的索引、在提交时检查的外键、`SET DEFAULT` 以及表达式上的索引。
- 注释不会保留；计划会说明这一点。
- 排序规则是 SQLite 自己的：`BINARY`、`NOCASE` 和 `RTRIM`。
- 保存为表的行，或加载到表中的文件，会和表一起一次性到达。

## 报告

目录中的 **系统** 包含八个报告。它们像表一样读取，可以排序、筛选、下载和绘制图表。**查看语句** 显示报告执行的 SQL。

- **文件**：页大小和页数、文件大小、空闲页、编码、日志模式、自动清理，以及文件保存的版本号。
- **完整性**：SQLite 对每一页的快速检查：`ok`，或损坏之处。它会读取整个文件，因此只在打开时读取。
- **损坏的外键**：键不指向任何内容的行，由没有强制执行外键的程序写入。
- **触发器**，以及它们的定义。
- 此服务器的 SQLite 提供的 **函数**、**模块** 和 **排序规则**，以及构建它时使用的 **编译选项**。

## 目录操作

- **重命名** 表或视图。引用表的内容会跟随它。视图会以新名称重新创建；按旧名称读取它的视图会拒绝重命名，并被指出。
- **删除** 一个或多个关系。删除会先试做并撤销，因此确认问题会显示它将做什么：随之删除的触发器、指向它的表、读取它的视图。如果指向它的表仍有行且不级联删除，删除会因此被拒绝。相互指向的表可以一起删除。
- **从 CSV 加载** 用文件在 `main` 中创建一张表，每一列都是 `TEXT`。
- **模型代码** 把 `main` 或所选内容写出，用于 ORM 或图表。

## 复制表

在目录中 **复制** 表，然后把它们 **粘贴** 到另一个 SQLite 连接或本连接的 `main` 中。它们会带着文件写下的列、键、检查、索引以及 `STRICT` 等选项一起到达；窗口询问的内容与 PostgreSQL 相同，显示每条语句，在点击 **复制** 之前不执行任何操作。

- 触发器会留下，并在窗口中列出。视图和虚拟表不能这样复制。
- 索引按新表命名，因为同一文件中的两个索引不能同名。
- 复制是一个事务：表、它们的行和索引要么一起到达，要么都不到达。外键在副本中不指向任何内容的行会使复制在最后失败，什么也不会留下。

粘贴到其他类型连接中的行，按任何表的行的方式处理。

## 备份

目录操作菜单中的 **备份** 与 PostgreSQL 的用法相同，针对连接打开的文件。

- 备份是由 SQLite 自己制作的文件副本，因此即使有人正在写入文件，它也是完整的。
- **恢复** 用备份替换文件中的全部内容。不是 SQLite 数据库的文件，或 SQLite 认为已损坏的文件，会在写入任何内容之前被拒绝。

## SQL 控制台

左侧栏 **查询** 下的 **新建查询** 会在连接上新建一个查询，表上方的 **作为查询打开** 会在该表上新建一个查询。它的工作方式与 PostgreSQL 控制台相同 —— 读取、立即提交或保留在 **手动** 事务中的修改、**解释**、补全和格式化。SQLite 在事务中修改结构，因此 `CREATE`、`ALTER` 或 `DROP` 属于包围它的事务，可以保留在手动事务中，并且在控制台询问你之前会先试做并撤销。

- 模式始终是 `main`。
- 参数写作 `:name`。
- `ANALYZE`、`VACUUM` 和 `REINDEX` 在事务之外单独运行。
- 报告信息的 `PRAGMA`（例如 `PRAGMA table_info(items)` 或 `PRAGMA integrity_check`）是读取。设置值的 `PRAGMA` 不会执行。
- 文件声明的外键会被强制执行，而 SQLite 自身只在程序要求时才这样做。
- 不能在控制台中修改触发器，也不能从中打开其他文件（`ATTACH`）。
- **解释** 显示 SQLite 的计划：每一步一行，没有成本，因为 SQLite 不提供成本。
- **停止** 和时间限制会让语句停在当前位置。
- 在你保留的事务中失败的语句会让事务保持打开。

## SQLite 在这里尚未具备的功能

- SSH 服务器上的文件，或其他连接中的文件，不能作为数据库打开。
