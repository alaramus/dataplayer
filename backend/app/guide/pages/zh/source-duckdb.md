# DuckDB

你个人存储中的 DuckDB 数据库文件。你可以浏览它的模式、表和视图，按页读取行，
查看表的结构，并阅读文件为它保存的 DDL。
连接的一般用法见[连接](connections.md)页面。

## 你可以看到的内容

- 模式、表和视图，以及它们经过排序和筛选的行
- 表的列、键、检查和索引，以及它引用的表
- 文件保存的关系 DDL，连同其索引
- 列表、结构和映射，以 JSON 显示
- 你所写 SQL 的结果，以及 DuckDB 的查询计划
- 关于文件的报告：它的大小、序列、类型、宏以及 DuckDB 的函数
- 表、视图或报告的全部行，以下载方式获取

## 你可以更改的内容

- 表数据：编辑单元格、粘贴区块、插入和删除行
- 列、索引和唯一键
- 新表，逐个对象设计或由行创建
- 创建和删除模式；重命名和删除表与视图
- 连同结构复制的表，复制到另一个 DuckDB 文件或本文件
- 整个文件的备份与恢复
- 通过控制台中的 SQL 更改数据和结构

## 连接

窗口的**连接**页面会询问：

- **数据库文件**：文件在你个人存储中的路径，例如 `data/shop.duckdb`。请先通过
  **文件**连接把文件放到那里。存储之外的路径会被拒绝。
- **文件不存在时创建**：勾选它可从空数据库开始。不勾选时，不存在的文件无法通过
  检查，输错路径也不会留下空文件。文件夹必须已经存在。

每次请求都会重新打开文件，并在请求结束后关闭，因此在两次请求之间，你自己的
DuckDB、笔记本或脚本也能打开它。当另一个程序占用它时，此连接会提示文件正在
使用中。

由比本服务器更新的 DuckDB 写入的文件可能无法打开；由本服务器（DuckDB 2）写入
的文件可能无法在 DuckDB 1 中打开。

无论文件里有什么，连接到它都不能：读取你个人存储之外的文件、访问网络、安装或
加载扩展，或把大型排序溢写到磁盘。文件中读取别处文件的视图在打开时会被拒绝。
你存储中的文件从其根目录用 `~/` 命名，例如 `~/data/sales.parquet`。

## 你自己的数据库

**新建连接** 提供 **在此处创建 DuckDB**，方式与启动服务器的两种方式相同。**为我设置好** 会在你的存储中创建 `databases/dataplayer.duckdb`，填入一个包含组织、人员、项目和任务的实验数据集，并为你保存连接。**让我选择** 会询问名称、文件夹以及是否填入数据。已被占用的名称会加上编号，而不是替换文件。这个文件是普通文件：可以在 **文件** 中重命名、下载或删除它。

你已经在 **文件** 连接中看到的 DuckDB 文件可以从那里连接：**作为 DuckDB 连接** 会为你填好这个窗口。

## 目录

- 第一层是文件的模式，其中包括 `main`。
- 每个模式里是它的表和视图。点击一个即可在标签页中打开它的行。
- 表会显示大致的行数，这是 DuckDB 不经计数得出的估计。
- **详情**显示一个关系有多少列、索引和约束。
- **查看 DDL** 显示文件保存的 `CREATE TABLE` 或 `CREATE VIEW` 语句，后面是表的
  索引。
- DuckDB 会自行为约束命名，例如 `items_id_pkey`，即使语句为它指定了名称。

## 读取行

表以网格打开，每次一页，排序和筛选方式与 PostgreSQL 表相同。列提供的操作取决于
其类型：数字、日期和文本可比较；UUID、枚举和间隔可判断等于或不等于；文本、
JSON、列表和结构可用“包含”和“开头是”；任何列都可判断为空或不为空。

- 分页按主键进行，没有主键时按 DuckDB 保存行的顺序。视图按 DuckDB 返回的顺序。
- 列表、结构或映射不能排序。
- 筛选值由 DuckDB 按列的类型读取：日期写作 `2026-01-02`，时刻带时区，小数精确到
  最后一位。DuckDB 无法按该类型读取的值会被拒绝。
- 在文本筛选中输入的 `%` 或 `_` 按字面查找。文本筛选不区分大小写。

值按 DuckDB 的写法显示：

- 大整数和小数精确显示；
- 带时区的时刻以 UTC 显示；
- 二进制值以十六进制显示，例如 `0xAA00`；
- 间隔显示为 `1 year 2 days 03:00:00`；
- 列表、结构、映射或联合（union）以 JSON 显示。

## 修改行

拥有 **编辑行** 权限时，可以像 PostgreSQL 表一样在网格中编辑表：双击单元格、粘贴区块、**插入行**、勾选行并 **删除所选行**。

- 行通过主键重新找到。没有主键的表可以接收新行，其余操作只读，因为 DuckDB 在更新时会移动行，而且可能存有两行完全相同的数据。视图是只读的。
- 如果在你读取之后有人修改了这一行，你的修改会被拒绝，而不会覆盖对方的修改。请重新加载后再试。
- 按网格显示的方式书写值：日期写作 `2026-01-02`，时刻带上时区，二进制写作 `0x…`。DuckDB 按列的类型读取它们，无法读取的值会被拒绝；在粘贴的区块中会指出被拒绝的单元格，且不会写入任何内容。
- 列表、结构、映射和生成列不能在网格中编辑；请在控制台中用 SQL 修改。
- 违反表的键、检查或必填列的修改不会执行，并会说明是哪条规则拒绝了它。
- 对于被其他行引用的行，DuckDB 无法更改其键列或唯一列，即使改成没人使用的值也不行；该行的其他列可以更改。
- 外键单元格有一个箭头，可打开它指向的行，**指向此行的内容** 会打开指向这里的行。

## 更改结构

表的 **结构** 会像修改 PostgreSQL 表那样修改它：添加、重命名和删除列，设置或移除默认值，要求或不再要求值，更改类型，添加和删除索引，添加唯一键。

- DuckDB 在原处完成每项修改，在一个事务中进行；不会重建任何东西。
- 与现有行相矛盾的修改不会执行，并会显示数量：没有值的行、无法转换为新类型的值、重复的值。
- 默认值在设置之前会按列的类型检查。
- DuckDB 无法为已存在的表添加外键或检查约束，也无法删除它的任何约束，包括主键。请改为把表复制到按你需要设计的表中。
- 带有自身索引的表，或被其他表的外键指向的表，只接受新列、默认值和新索引。重命名、删除列或更改其类型、要求值以及添加唯一键都会被拒绝。
- DuckDB 重命名和删除列时不会检查读取该列的视图，因此修改之后会重新读取每个视图，会被这次修改破坏的视图会按名称拒绝它。
- DuckDB 自己拒绝的操作，例如删除索引覆盖的列，会用 DuckDB 自己的原话说明。
- 提供的类型是 DuckDB 的：文本、四种宽度的整数、浮点数、小数、布尔值、日期、时间、带或不带时区的日期和时间、间隔、UUID、JSON 和二进制。
- DuckDB 只构建一种索引——自适应基数树，以表及其列命名。约束由 DuckDB 自行命名。

## 创建表

模式操作菜单中的 **创建表** 会打开表设计器，与 PostgreSQL 相同。计划是一条 `CREATE TABLE`、每个索引一条 `CREATE INDEX` 以及注释，一起执行：表要么完整创建，要么完全不创建。

- 标识列是它自己的序列 `<表>_<列>_seq`，在表之前创建，列的默认值取它的下一个值。它可以从任意值开始，并以任意步长递增。它接受你写入的值，因此不能是 ALWAYS。
- 生成列在每次读取时计算；要求存储的生成列也按这种方式创建，并给出警告。
- DuckDB 没有的功能会在你审阅计划之前标记在提出要求的对象上：不记日志的表或分区表、级联、置空、置为默认值或指向其他模式的外键、在提交时检查的键、只覆盖部分行或附带额外列的索引。
- 默认值在制定计划时按其列的类型检查。
- 你给出的约束名称不会保留；DuckDB 自行为约束命名。
- 表及其列的注释会保留。
- 排序规则是 DuckDB 自己的：`NOCASE`、`NOACCENT` 和 `NFC`。
- 保存为表的行，或加载到表中的文件，会与表一次性一起到达。DuckDB 无法按其列类型读取的值会使表不被创建。

## 报告

目录中的 **系统** 包含五个报告。它们像表一样读取，可以排序、筛选、下载和绘制图表。**查看语句** 显示报告执行的 SQL。

- **数据库**：DuckDB 的版本、文件大小、已用和空闲的块，以及预写日志。
- **序列**，包括每个序列的起点、步长和边界。表设计器创建的标识列就是其中之一。
- 文件自己的 **类型**：枚举、结构以及类型的其他名称。
- **宏**：用 SQL 编写并保存在文件中的函数，包括参数和函数体。
- DuckDB 内置的 **函数**，以及每个函数有多少个签名。
- 引擎的设置不会显示：其中包含服务器的文件夹，而且在这里是固定的。

## 目录操作

- **新模式** 位于连接的顶层。**删除模式** 可删除除 `main` 以外的任何模式；含有内容的模式需要勾选 **同时删除其中的所有内容**，确认问题会列出将被删除的内容。DuckDB 中模式不能重命名。
- **重命名** 表或视图。之后会重新读取每个视图，读取旧名称的视图会拒绝重命名并被指出。DuckDB 不会重命名带有自身索引的表，也不会重命名被其他表的键指向的表。
- 带有自身外键的表不会被重命名：DuckDB 会在它指向的表中保留旧名称，那张表此后既不能删除行，也不能被删除。
- **删除** 一个或多个关系。删除会先试做并撤销，因此确认问题会指出将无法使用的视图。被其他表的键指向的表会被拒绝删除，除非那张表也一起删除。只有被删除的表从中取值的序列（例如标识列的序列）会一并删除。
- **从 CSV 加载** 用文件在该模式中创建一张表，每一列都是 `VARCHAR`。
- **模型代码** 把模式或所选内容写出，用于 ORM 或图表。
- 不会在模式之间移动任何内容：DuckDB 做不到。

## 复制表

在目录中 **复制** 表，然后把它们 **粘贴** 到另一个 DuckDB 连接或本连接的某个模式中。它们会连同列、默认值、键、检查约束、索引和注释一起到达；窗口询问的内容与 PostgreSQL 相同，会显示每条语句，在点击 **复制** 之前不执行任何操作。

- 每个值都会原样到达，包括列表、结构和映射。带有 `UNION` 列的表不会被复制：它的文本无法说明值属于哪个成员。
- 默认值取自序列下一个值的列（例如标识列）会在副本中获得自己的序列，并从原序列接下来的值继续。
- DuckDB 会立即检查外键，因此一张表会在它所指向的副本中的表之后创建并填充。键只能指向它自己的模式。
- 复制是一个事务：表、它们的行和索引要么一起到达，要么都不到达。

## 备份

目录操作菜单中的 **备份** 与 PostgreSQL 的用法相同，针对连接打开的文件。

- 备份是文件的一份副本，在 DuckDB 把日志写入文件之后生成。当其他程序正在写入文件时，备份会被拒绝。
- **恢复** 会用备份替换文件中的全部内容。不是 DuckDB 数据库的文件会在写入任何内容之前被拒绝。

## SQL 控制台

左侧栏 **查询** 下的 **新建查询** 会在连接上新建一个查询，表上方的 **作为查询打开** 会在该表上新建一个查询。它的工作方式与 PostgreSQL 控制台相同 —— 读取、立即提交或保留在 **手动** 事务中的修改、**解释**、补全和格式化。DuckDB 在事务中修改结构，因此 `CREATE`、`ALTER` 或 `DROP` 属于包围它的事务，删除操作会在控制台询问你之前先试做并撤销。

- 存储中的文件以 `~/…` 读取，例如 `SELECT * FROM '~/data/sales.parquet'`。用 `INSERT INTO t SELECT * FROM '~/data/sales.csv'` 把文件加载到表中。
- 参数写作 `$name`。
- 模式在编辑器上方选择；`USE` 和 `SET` 不会执行。
- 不会执行，并各自说明原因：`ATTACH`、`COPY`、`EXPORT` 和 `IMPORT DATABASE`、`INSTALL` 和 `LOAD`、`PREPARE` 以及密钥。
- 保持的事务中有语句失败时，事务即告结束：只剩 **回滚**。
- 在你保持事务期间，文件一直打开，其他程序无法打开它。
- 由于 DuckDB 没有保存点，在保持的事务中无法先试运行删除；请在自动提交模式下运行。
- **解释** 显示 DuckDB 的计划：其算子以及预计的行数。
- **停止** 和时间限制会让语句停在当前位置。

## DuckDB 在这里还没有的功能

- SSH 服务器上或其他连接中的文件不能作为数据库打开。
