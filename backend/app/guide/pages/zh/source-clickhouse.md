# ClickHouse

通过 HTTP 接口连接的 ClickHouse 服务器。你可以浏览数据库，分页读取表和视图，查看表的结构、服务器生成的 DDL，并在控制台中运行 SQL。连接的一般说明见[连接](connections.md)页面。

## 你可以看到的内容

- 数据库、表、视图和物化视图
- 由服务器排序和筛选的行，以及原样存储的值
- 列、主键和排序键、跳数索引及检查约束
- 服务器生成的关系 DDL
- 表的大小、分区和最近写入时间
- SQL 查询结果和服务器的查询计划
- 下载为文件的所有匹配行
- 服务器的查询、变更、合并、表大小、磁盘和设置
- 仪表板上的服务器计数器

## 你可以更改的内容

- 表数据：编辑单元格、粘贴数据块、插入和删除行
- MergeTree 表的列和跳数索引
- 逐个对象设计的新表，或由行生成的新表
- 创建和删除数据库
- 重命名、移动或删除表和视图
- 将表及其结构复制到另一个 ClickHouse 连接
- 备份和恢复此连接的数据库
- 在控制台中用 SQL 更改数据和结构，每次执行一项更改

## 连接

窗口中的**连接**页面会询问：

- HTTP 接口的**主机**和**端口**：8123，或启用 TLS 时使用 8443。不是原生端口 9000；
- **TLS**：使用 HTTPS，并验证服务器证书。ClickHouse Cloud 需要 TLS；
- **身份验证**：用户名和密码，或无密码用户。未指定其他用户时使用 `default`；
- **数据库**：打开目录时显示的数据库。可以留空；用户可见的所有数据库仍会显示在目录中。

将 `clickhouse://ann@ch.example.com:8123/logs` 这样的连接字符串粘贴到 **URL**，即可填入这些字段。也支持 `https://ch.example.com:8443`，`?secure=true` 会启用 TLS。粘贴字符串中的密码会移入密码字段，并从字符串中删除。

支持 ClickHouse 23.8 及更高版本。检查连接时会拒绝更旧的服务器，并说明其版本。不能使用配置了 `readonly = 1` 的用户：每次读取都会发送自己的设置，而该用户可能无权设置这些选项。

## 目录

- 第一层是数据库。连接指定的数据库排在最前；`system` 和 `information_schema` 属于服务器，并会标记出来。
- 数据库中包含表、视图和物化视图。物化视图保存数据的底层表不会显示在旁边，需通过该视图读取。
- 对于 MergeTree 表，服务器会显示行数和表大小；其他引擎不提供这些信息。

## 读取行

- 数值会按存储值精确显示，包括 `UInt256` 或 `Decimal` 的最后一位。
- 所有时间都以 UTC 和 `Z` 显示，不受列的时区影响。筛选值未带时区偏移时也按 UTC 读取。
- 数组、Map 和 Tuple 显示为 JSON。
- 文本列中不是 UTF-8 的字节会显示为替换字符。
- ClickHouse 的键都不唯一，因此表页先按排序键，再按其他所有列排序；下一页不会重复最后一行。引擎从外部读取数据（例如 URL、文件或流）的表，以及 `system.numbers` 这样的无限表，按引擎提供的顺序读取。

## 修改行

- 可以编辑 MergeTree 表的单元格、粘贴数据块、插入和删除行。Log、TinyLog、StripeLog、Memory、Buffer 和 Distributed 表只接受插入行。视图、读取外部数据的表和服务器自带的表都不能修改。
- ClickHouse 没有区分行的唯一键，因此根据一行的所有值定位。对读取者而言，所有值都相同的行就是同一行：编辑其中一行会更改全部，删除一行会删除全部。删除后的数量会说明删掉了多少行。
- 如果两行只在浮点数、Map 或 JSON 列上不同，就无法区分，因此不会修改，并会显示原因。
- 如果有人在你读取之后修改了一行，你的修改会被拒绝，避免覆盖对方的修改。重新读取页面后再试。与此操作同时发生的修改无法检测：ClickHouse 没有锁住该行的事务。
- 排序键、主键或分区键的列、计算列、Map 和 JSON 列均不可编辑。ClickHouse 根据键决定行的存放位置，不能移动这些行。
- 服务器会按列类型读取值，不符合类型的值会被拒绝。粘贴的数据块要么全部写入，要么全部不写入，不符合要求的单元格会被标记。时间按页面显示的 UTC 读取；数组和元组按页面显示的 JSON 写入。
- 使用 `enable_block_number_column` 和 `enable_block_offset_column` 创建的表通过轻量级 `UPDATE` 修改。其他表通过 mutation 修改，mutation 会重写受影响的数据部分：少量行适用，粘贴数百行时会很慢。
- 新行要等重新读取页面后才有行标识，因此无法立即编辑。

## 更改结构

- 可以添加、重命名和删除 MergeTree 表的列，设置默认值、调整是否允许空值以及更改类型；也可以创建和删除跳数索引。不会修改其他引擎或视图。
- 排序键、主键或分区键的列不能删除、重命名或更改：ClickHouse 根据键决定行的存放位置。
- 更改类型之前，服务器会统计新类型无法容纳的值；将列设为必填之前，会统计没有值的行。只要任一数量大于零，就不会更改：ClickHouse 在列定义更改后才转换行，转换失败会使表无法读取。如果仍然失败，会停止操作并恢复原类型。会丢失信息的值（例如把 `1.5` 转成整数）也算作无法容纳。
- 更改类型会在磁盘上重写整张表，耗时取决于表的大小。
- 跳数索引可以是 min-max、最多包含一百个值的集合，或针对所选列的 Bloom 过滤器。已存在的行也会建立索引。索引不唯一，主键不能删除。
- ClickHouse 不支持创建唯一键或外键。

## 创建表

- 在数据库上选择**创建表**会打开表设计器。执行前会显示计划；计划只包含一条用于创建 MergeTree 表的 `CREATE TABLE`。
- 主键会成为表的排序键：ClickHouse 按此顺序保存和查找行，但不会阻止多行使用同一个键。键列必须有值。没有主键时，按行到达的顺序保存。
- 可以为空的列使用 `Nullable`；数组或 JSON 列始终有值。计算列在写入行时计算。
- 当前时间、今天的日期和随机 UUID 可用于默认值或计算列。
- ClickHouse 不支持唯一键、外键、标识列、排序规则，也不支持按范围、列表或哈希分区。设计器会在相应对象上说明这一点。
- 从页面行创建的表是 MergeTree，所有列都可以为空。如果拒绝写入这些行，不会留下该表。

## System 区域

- 数据库之后的 **System** 区域显示服务器自身的信息：**Processes**、**Mutations**、**Merges**、**Table sizes**、**Disks**、**Changed settings**、**Metrics** 和 **Users**。这些报告可以像表一样排序、筛选和分页。Processes、Mutations、Merges 和 Metrics 每隔几秒重新读取。
- 在 **Processes** 中选择查询并使用 **Cancel query** 停止。查询已经写入的数据仍会保留。
- 在 **Mutations** 中，**Stop mutation** 会停止重写表数据部分的变更。持续失败的 mutation 会阻塞该表之后的所有变更；错误显示在最后一列。停止它后即可再次修改表。
- 目录中也有完整的 `system` 数据库，可用于查看这些报告未涵盖的内容。

## 搜索和下载

- 搜索框可按名称查找数据库和表，也可根据列名、列注释或表注释查找表。`%` 和 `_` 是普通字符。
- **下载**会导出符合页面筛选条件和排序规则的所有行，而不只是当前页。

## 目录操作

- 在连接的顶层选择**新建数据库**。
- 在数据库上可选择**创建表**、**从 CSV 加载**、**删除数据库**和**建模为代码**。只有查看数据库内容并确认删除其中所有内容后，才会删除数据库。
- 在表或视图上可选择**重命名**、**移动到数据库**、**删除**和**建模为代码**。删除前会列出读取此表、之后将无法工作的物化视图。普通视图不会列出：服务器不记录视图读取了哪些表。
- CSV 文件会生成一张所有列均为文本且允许为空的表。
- 如果表超过服务器的删除限制，服务器会拒绝删除并说明原因。默认限制为 50 GB，管理员可以修改。
- 这里的更改无法撤销：ClickHouse 会立即保存每项更改。

## 复制表

在目录中**复制**表，再将它们**粘贴**到此连接或其他 ClickHouse 连接的数据库中。复制内容包括列、默认值、计算列、编解码器、注释、跳数索引、检查约束、引擎、键和设置。窗口会像 PostgreSQL 一样询问相关选项，显示每条语句；在点击**复制**前不会执行任何语句。

- 会复制 MergeTree 系列以及 Log 和 Memory 引擎的表。不会复制复制型表、视图，以及基于文件、URL、流或其他服务器的表；窗口会说明原因。
- 读取被复制表的物化视图会保留在原处，窗口会列出它们。
- 先创建表，再复制行。如果复制失败或被停止，已创建的表会被删除。
- 读取期间不会锁定表：期间写入的行可能会复制，也可能不会。

粘贴到其他类型连接的行与粘贴到任何表的行一样传输。

## 备份

目录操作菜单中的**备份**与 PostgreSQL 的操作相同，针对连接指定的数据库。未指定数据库的连接不提供备份。

- 备份是一个文本文件，包含创建每张表、视图和物化视图的语句，以及每张表的所有行。其他引擎的表（例如复制型表）会在文件中列为未包含。
- 表会逐个读取，而不是在同一时刻读取。
- **恢复**会删除并重新创建备份中的每张表和视图。数据库中存在但备份未包含的内容会保留。只能恢复到同名数据库，并且目标 ClickHouse 版本必须与备份相同或更新。

## 仪表板

ClickHouse 连接可以向仪表板提供数据。**ClickHouse server** 布局显示连接数和运行中的查询、每秒查询数、读取、插入和合并的行数、内存、网络流量、活动数据部分、失败查询，以及该连接数据库的大小。计数器反映整个服务器。

## 启动自己的服务器

**新建连接**提供**在此启动 ClickHouse**：在此机器上启动服务器，并保存为使用 `default` 用户登录的连接。该用户也可以管理用户和授权。启用示例数据后会打开 `demo_lab`，其中有组织、人员、项目及其任务，还有二十万次页面访问；每个界面都有示例数据，包括分区、TTL、编解码器、跳数索引、ReplacingMergeTree、SummingMergeTree、两个由页面访问数据驱动的物化视图、一个视图和一张 Log 表。

## SQL 控制台

左侧栏 **Queries** 下的**新建查询**会在此连接上启动查询；表上方的**作为查询打开**会针对该表启动查询。它的读取、修改、**Explain**、补全和格式化方式与 PostgreSQL 控制台相同，但有以下区别：

- 编辑器上方选择的数据库是默认数据库；一次只能选择一个。
- 没有 **Manual** 事务，也不会预先试运行：ClickHouse 会立即保存每项更改，且无法撤销。因此，插入、删除、更改或创建内容的语句都会单独运行。修改脚本须逐条运行；读取查询可以一起运行。
- 读取查询使用服务器的 `readonly` 设置，由服务器拒绝任何写入操作。
- `ALTER TABLE … DELETE` 和 `UPDATE` 会在语句结束前完成，因此下一次读取能看到修改后的行。
- 参数采用 ClickHouse 语法 `{name:Type}`。服务器按指定类型读取值，不符合类型时会拒绝；**SQL null** 会向 `Nullable` 类型发送 NULL。值的读取方式与 clickhouse-client 的 `--param_` 相同，因此反斜杠会开始转义序列。
- `INSERT INTO t FORMAT JSONEachRow` 后面可以跟随数据行；`SHOW`、`DESCRIBE`、`EXISTS`、`CHECK TABLE` 和 `EXPLAIN AST`、`SYNTAX`、`PIPELINE`、`ESTIMATE` 也可以运行。普通 `EXPLAIN` 对应 **Explain**。
- 不会运行 `SET` 和 `USE`（改为在语句中使用 `SETTINGS`，并在编辑器上方选择数据库）、`SYSTEM`、`DETACH`、`ATTACH`、用户、角色、授权、函数，以及 `SELECT` 上的 `FORMAT`，因为控制台会自行显示结果。
- **停止**按钮和时间限制会通过 `KILL QUERY` 结束语句。
