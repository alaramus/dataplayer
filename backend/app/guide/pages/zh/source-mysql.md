# MySQL

MySQL 或 MariaDB 服务器。你可以浏览它的数据库，按页读取表和视图，查看表的结构，阅读服务器自己写出的 DDL，并在控制台中运行 SQL。连接的一般用法见 [连接](connections.md) 页面。

## 你可以看到的内容

- 数据库、表和视图，以及在服务器上排序和筛选的行
- 表的列、键、检查和索引，以及它引用的表
- 行的外键指向哪里，以及哪些内容指向它
- 关系的 DDL，即服务器写出的形式
- 表的大小，以及它的创建时间和最后写入时间
- 你编写的 SQL 的结果，以及服务器对查询的执行计划
- 所有匹配的行，下载为文件
- 服务器正在做什么：进程、变量、状态、用户、例程、触发器、事件和引擎

## 你可以更改的内容

- 表数据：编辑单元格、粘贴块、插入和删除行
- 列、索引、唯一键和外键
- 新表：逐个对象设计，或由行生成
- 通过控制台中的 SQL 更改数据和结构
- 其他连接正在运行的内容：可以停止它的语句，或关闭该连接
- 数据库：创建和删除
- 表和视图：重命名、将表移动到另一个数据库、删除
- 连同结构一起复制到另一个 MySQL 或 MariaDB 连接的表
- 连接所指数据库的备份，以及从备份恢复的数据库

## 连接

窗口的 **连接** 页面要求填写：

- **主机** 和 **端口**，除非服务器另有说明，否则为 3306；
- **身份验证**：用户和密码，或没有密码的用户；
- **数据库**：目录从这里打开。可以留空。无论如何，用户可见的每个数据库都会出现在目录中。

将 `mysql://ann@db.example.com:3306/sales` 这样的连接字符串粘贴到 **URL** 中会填好这些字段；`mariadb://` 也以同样方式读取。粘贴的字符串中的密码会移到密码字段，并从字符串中移除。

服务器提供 TLS 时连接会加密，不提供时保持明文。不检查服务器的证书。

支持 MySQL 8.0.16 及以上版本和 MariaDB 10.6 及以上版本。更旧的服务器在检查连接时会被拒绝，并显示其版本。

## 目录

- 第一层是数据库。连接所指的数据库排在最前；`mysql`、`information_schema`、`performance_schema` 和 `sys` 属于服务器，并有相应标记。
- 数据库中是它的表和视图。点击其中一个会在标签页中打开它的行。
- 表会显示大约有多少行。这个数字是服务器的估计值，MySQL 最多可能保留一天，不会实际计数。
- **详情** 显示关系有多少列、索引和约束，大小多少，以及创建时间和最后写入时间。
- **查看 DDL** 显示服务器本身给出的 `CREATE TABLE` 或 `CREATE VIEW` 语句。
- 数据库之后的 **系统** 是服务器关于自身的报告区（见下文 **报告**）。
- 顶部的搜索可按名称查找数据库和表，并可按列以及表和列上的注释查找表。

## 读取行

表以表格形式按页打开，像 PostgreSQL 表一样由服务器排序和筛选。列提供的操作取决于其类型：数字、日期和文本可以比较；文本可用“包含”和“开头是”；枚举可用相等和“列表之一”；每一列都可用“为空”或“不为空”。

- 分页按主键进行。没有主键的表按不可为空的列上的唯一键进行，这也是 InnoDB 保存此类表的顺序。两者都没有的表以及视图，按服务器返回的顺序排列。
- 在文本筛选中输入的 `%` 或 `_` 按字面查找。
- **下载** 会询问 **当前页** 还是 **所有匹配的行**。每一行在写入文件的同时从服务器读取，按页面的顺序并带有它的筛选条件。

值的显示方式：

- `DECIMAL` 和大的无符号整数与存储的完全一致；
- `BIT` 显示为数字；
- `TIMESTAMP` 以 UTC 显示，带 `+00:00`。`DATETIME` 按写入时的样子显示，没有时区，因为它本来就没有；
- `TIME` 按 MySQL 写出的样子显示，可能为负数或超过 24 小时；
- 像 `0000-00-00` 这样的零日期按服务器写出的样子显示；
- 几何数据以文本显示，例如 `POINT(1 2)`；
- 二进制列以十六进制显示，例如 `0x00FF`。

## 修改行

拥有 **编辑行** 权限时，表在其表格中的编辑方式与 PostgreSQL 表相同：双击单元格、粘贴块、**插入行**、勾选行并 **删除所选行**。

- 行通过主键重新找到，或通过不可为空的列上的唯一键找到。两者都没有的表，其行通过全部值找到，每次只修改一行：所有值都相同的行可以互换。两行若仅在浮点、JSON 或几何列上不同，则无法区分，对其中一行的修改会因此被拒绝。
- 如果在你读取一行之后有人修改了它的任何一列，你的修改会被拒绝，而不会覆盖对方的修改。请重新加载后再试。
- 列无法容纳的值会在写入任何内容之前被拒绝，并指出包含此类值的单元格。粘贴的块只有在全部都能写入时才会写入。
- 按表格显示的方式书写值：二进制写成 `0x…`，几何写成 WKT，例如 `POINT(1 2)`，`TIMESTAMP` 带上时差。
- 外键中的单元格有一个箭头，可以打开它指向的行；**指向此行的是什么** 会打开指向此处的行，无论在这个数据库还是服务器上的其他数据库中。

## 更改结构

表的 **结构** 与 PostgreSQL 表一样修改：添加、重命名和删除列，设置或移除默认值，要求或不再要求值，更改类型，添加和删除索引、唯一键和外键。

- 更改列的类型或可空性时，列的其他属性——默认值、注释、字符集、AUTO_INCREMENT——都会保留。
- 与现有行相矛盾的更改不会执行，并显示数量：没有值的行、重复的值、指向不存在内容的行、新类型无法容纳的值。最后一种 MySQL 只能在尝试更改并被拒绝之后才能统计；无论哪种情况都不会改动任何内容。
- 提供的类型是 MySQL 的：文本、长文本、整数、大整数、小数、浮点数、0 或 1 的布尔值、日期、日期和时间、时间戳、JSON，以及文本形式的 UUID。
- 索引可以是 B 树、全文（仅文本列）或空间（一个不可为空的几何列）。新索引或新键由 MySQL 自行命名。
- 在 MySQL 中，唯一键和它的索引是同一个东西；请按键来删除它。
- 外键不提供 `SET DEFAULT`：InnoDB 不会执行它。

## 创建表

数据库操作菜单中的 **创建表** 会打开表设计器，与 PostgreSQL 相同。计划是一条 `CREATE TABLE`，其中包含每个键、检查、外键和索引，因此表要么完整创建，要么完全不创建。

- MySQL 不具备的功能，会在你审阅计划之前标记在要求它的对象上：可延迟的键、索引附带的额外列、只覆盖部分行的索引、空值排在最前或最后、不记录日志的表或分区表。
- 标识列就是 AUTO_INCREMENT：每表一个，位于某个键的首位，有起始值但没有自己的步长。
- 主键总是叫 PRIMARY。
- 作为表保留的行或加载到表中的文件，会在创建表之前按所选类型检查；如果仍被拒绝，新表会被再次删除。

## SQL 控制台

左侧栏 **查询** 中的 **新建查询** 会在连接上开始一个查询，表上方的 **作为查询打开** 会在该表上开始一个查询。它的工作方式与 PostgreSQL 控制台相同——读取、立即提交或保留在 **手动** 事务中的更改、**解释**、补全和格式化——区别如下：

- 编辑器上方选择的数据库就是默认数据库，相当于执行了 `USE`；一次一个数据库。
- 参数写作 `:name`。每个值都以文本发送，因此服务器需要作为数字的值（例如 `LIMIT` 之后的数字）不能作为参数。
- 结构更改——`CREATE`、`ALTER`、`DROP`、`TRUNCATE`、`RENAME`——单独运行。MySQL 会立即提交它，连同它之前的一切，因此它不能与其他语句一起运行，不能在你持有的事务中运行，也不能先试运行。控制台在运行之前会询问，并说明这一点。
- 在你持有的事务中失败的语句会让事务保持打开；死锁会结束事务。
- **停止** 和时间限制通过 `KILL QUERY` 结束语句。
- 用户、权限、例程、触发器和事件不在控制台中更改。`LOAD DATA`、`SELECT … INTO OUTFILE` 和 `CALL` 不会运行。

## 报告

目录中的 **系统** 包含关于服务器的八个报告。它们像表一样读取，可以排序、筛选、下载和制作图表。**查看语句** 会显示报告运行的 SQL。

- **进程**：当前打开的连接以及各自正在运行的内容。每一行都有 **取消查询**（停止语句并保留连接）和 **终止**（关闭连接）。报告每五秒自动重新读取一次。
- **变量**：服务器的每项全局设置。
- **状态**：服务器自启动以来记录的计数器。每十秒自动重新读取一次。
- **用户**：允许连接的账户及其来源主机。行上方的 **新建用户** 会创建一个账户：名称、可连接的主机（`%` 表示任何地方）和密码。它不被授予任何权限，或在勾选时被授予读取连接所指数据库的权限。只有连接的所有者拥有此命令。
- 服务器自身数据库之外的 **例程** 和 **触发器**，以及其调度器运行的 **事件**。
- **引擎**：服务器提供的存储引擎，以及默认引擎。

报告只显示连接用户能看到的内容：没有 `PROCESS` 权限的用户只能看到自己的连接，无法读取 `mysql` 数据库的用户会被拒绝查看 **用户**。

## 目录操作

- 目录顶层的 **新建数据库**。
- **删除数据库** 会先询问。包含内容的数据库只有在勾选 **同时删除其中的所有内容** 时才会删除，并在你确认之前统计其中的内容。
- **重命名** 表或视图。指向表的外键会随之更新。
- **移动到数据库** 移动一张表。视图以及带触发器的表会留在原数据库中。
- **删除** 一个或多个关系。被选择之外的表引用的表不会删除，并会列出引用它的表。在 MySQL 中，读取被删除表的视图也会被列出。
- **从 CSV 加载** 由文件生成一张表，每一列都是 `TEXT`。
- **模型代码** 将数据库或所选内容写成 ORM 或图表可用的形式。

结构更改不会像在 PostgreSQL 中那样先预演：MySQL 会立即提交它们。

## 复制表

在目录中 **复制** 表，然后 **粘贴** 到另一个 MySQL 或 MariaDB 连接的数据库中，或粘贴到此连接中。它们会连同列、键、索引、检查和选项一起到达；窗口询问的内容与 PostgreSQL 相同，会显示每条语句，并且在点击 **复制** 之前不会运行任何内容。

- 触发器不会复制，会在窗口中列出。视图和分区表不能这样复制。
- 先创建表，然后再写入行。如果复制失败或被停止，它创建的表会被再次删除。
- MariaDB 使用了 MySQL 没有的排序规则，因此从 MariaDB 复制到 MySQL 的表可能会被拒绝；窗口会说明是哪一步拒绝的。

粘贴到其他类型连接中的行，按任何表的行的方式处理。

## 备份

目录操作菜单中的 **备份** 与 PostgreSQL 相同，针对连接所指的数据库。没有指定数据库的连接不会提供备份。

- 备份是一个 SQL 文件，由与服务器版本相同的 `mysqldump`（MariaDB 则为 `mariadb-dump`）写出，包含例程、触发器和事件。
- **恢复** 会删除并重新创建备份中的每个表、视图和例程。来自 MariaDB 的备份只能恢复到 MariaDB，来自 MySQL 的备份只能恢复到 MySQL。

## 仪表盘

MySQL 连接可以向仪表盘报告。布局名为 **MySQL 服务器**：连接、语句、行、缓冲池读取、网络流量、慢查询和中断的连接，以及连接所指数据库的大小。计数器针对整个服务器：MySQL 不按数据库记录它们。

## 你自己的服务器

**新建连接** 提供 **在此处启动 MySQL** 和 **在此处启动 MariaDB**：在本机启动的服务器，保存为以其 root 身份登录的连接。带示例数据时，它会打开在 `demo_lab` 上——组织、人员、项目、数百个任务和测量值——每个界面都有可看的内容：生成列、JSON、分区表、全文键和空间键、视图、触发器，以及一张没有键的表。

## MySQL 在这里尚未具备的功能

- 数据库不能重命名；MySQL 没有办法做到这一点。
