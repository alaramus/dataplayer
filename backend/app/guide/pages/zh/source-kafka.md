# Kafka

一个 Kafka 集群。你可以查看它的主题和消费者组，以行的形式读取主题的消息，并查看每个组滞后了多少。连接的一般用法见[连接](connections.md)页面。

## 你可以看到的内容

- 集群的主题、消费者组，以及单独列出的 Kafka 自身主题
- 主题的消息以行显示，最新的在前，可从任意时间或偏移量开始
- JSON 消息的字段，每个字段一列
- 主题的每个分区：leader、副本和偏移量
- 主题自身的设置
- 每个消费者组在每个分区中的位置及其滞后
- 集群的报告：broker、设置、需要关注的分区
- 仪表板上的滞后、每秒消息数和集群健康状况
- 按名称查找主题和组
- 将主题的消息下载为文件
- 终端中已为该连接配置好的 Kafka 自带工具

## 你可以更改的内容

- 发送消息，逐条发送或粘贴多行
- 新建主题及其分区和设置
- 删除主题、修改设置、增加分区
- 删除主题的消息：全部或早于某个时间的
- 将消费者组的位置移动到开头、末尾或某个时间
- 删除消费者组
- 在终端中进行 Kafka 工具能做的任何修改

## 连接

窗口的**连接**页面需要填写：

- **Broker**：一个或多个 broker 的 `host:port`，用逗号分隔。一个就够了：它会告诉 DataPlayer 其余的在哪里；
- **TLS**：加密连接，并验证 broker 的证书；
- **CA 证书**：签发证书的机构，PEM 格式，仅当系统尚未信任它时需要；
- **认证**：**无**，或通过 **SASL PLAIN**、**SASL SCRAM-SHA-256** 或 **SASL SCRAM-SHA-512** 使用用户名和密码。

DataPlayer 会连接 broker 自己公布的地址，因此这些地址必须能以这些名称从 DataPlayer 服务器访问。不支持 SSH 隧道。

## 目录

- **主题**、**消费者组**和**内部主题**——Kafka 自身的主题，例如 `__consumer_offsets`，名称以下划线开头。
- 主题显示它有多少个分区以及这些分区包含多少条消息。这个数字是上限：压缩主题中有空缺。
- 组显示它是稳定、正在重新平衡还是没有消费者，以及有多少个消费者。
- 每一层按名称显示前一千个。

## 主题的消息

- 每条消息一行：分区、偏移量、时间、键、值和消息头。
- 当值是 JSON 对象时，每个字段也是一列，名称为 `value.` 加字段名。字段取自最新的两百条消息。
- 不是文本的键或值以十六进制显示。
- 最新的在前，跨所有分区。按 **timestamp** 排序可从最旧的开始；其他列不能排序。
- 按 **partition**、**offset** 或 **timestamp** 筛选可决定读取从哪里开始、在哪里结束：无论主题多长，Kafka 都会自己找到那个位置。
- 对键、值、消息头和字段的筛选会在读取到的消息中查找，每页最多十万条。
- 一页最多从末尾往回一万条消息。要看更早的，请按时间或按分区和偏移量筛选。
- 读取主题不会加入任何消费者组，也不会移动任何人的位置。

## 发送消息

- 主题行上方的 **+** 会添加一条消息。填写你需要的内容：所有字段都可以留空。
- **partition** 留空则由 Kafka 按键选择；**timestamp** 留空即为当前时间。
- **key** 和 **value** 是文本；`0x` 后跟十六进制数字会作为这些字节发送。
- 将 **value** 留空并填写 `value.` 字段，即可发送由这些字段组成的 JSON 对象。
- **headers** 是由文本组成的 JSON 对象，例如 `{"source": "manual"}`。
- 粘贴到主题中的行会作为消息发送。如果某个值无法读取，则什么都不发送，并指出该单元格。
- 不能从此处写入 Kafka 自身的主题。

## 消费者组

- 组读取的每个分区一行：主题、分区、组提交的位置、分区末尾以及二者之间的滞后，还有正在读取它的消费者。这些行每十秒刷新一次。

## 详情面板

选中一个主题或组，然后在目录菜单中选择**详情**。

- 主题：消息数量，每个分区一行，含 leader、副本、同步副本和偏移量，以及主题自身的设置。
- 组：状态、消费者、总滞后、协调者 broker、分配策略和主题。

## Kafka 工具

Kafka 连接上的**终端**会打开 Kafka 自带的命令行工具（即其文档中使用的工具），并已指向该连接：它的 broker、TLS 和用户。输入工具时无需 `--bootstrap-server`：

- `kafka-topics.sh --list` —— 列出主题
- `kafka-console-consumer.sh --topic NAME --from-beginning` —— 读取主题；按 Ctrl+C 停止
- `kafka-consumer-groups.sh --describe --all-groups` —— 每个组的滞后

自行指定 `--bootstrap-server` 可让工具指向另一个集群。终端运行在 DataPlayer 服务器上的容器中，因此该服务器必须被允许运行容器，并且 broker 必须能从那里访问。

## 修改主题和组

在**主题**层勾选一个主题，然后打开目录菜单：

- **新建主题** —— 名称、分区数、副本因子（留空则使用 broker 的默认值）和设置，每行一个 `name=value`。
- **删除主题** —— 窗口会说明将删除多少条消息，以及哪些组在读取该主题。
- **修改设置** —— 打开时带有主题自身的设置；删除某一行即可将该设置恢复为 broker 的默认值。
- **增加分区** —— 分区只能增加，不能减少。此后某个键可能会落到另一个分区。
- **删除消息** —— 全部或早于某个时间的。此操作无法撤销。

在**消费者组**层勾选一个组，可**移动位置**：移到开头、末尾或某个时间，针对它的所有主题或其中一个。只有当该组没有消费者在运行时，位置才会移动。窗口会显示每个分区移动前后的情况。**删除组**会删除组及其位置，同样只能在无人读取时进行。

## 集群部分

目录顶部的**集群**汇集了集群关于自身的信息：**集群**（ID、控制器以及 broker、主题和分区的数量）、**Broker**、**Broker 设置**（与 Kafka 默认值不同的设置）和**需要关注的分区**（一切正常时为空）。第一个和最后一个每十秒刷新一次。

## 仪表板、搜索和下载

- **Kafka 集群**仪表板绘制每个组的滞后、每个主题的每秒消息数以及需要关注的分区，按名称取前一百个主题和组。
- 页眉中的搜索可按名称找到主题和组。
- 在主题上**下载**会保存其页面将显示的消息，包括筛选和顺序，每个分区从末尾起最多一万条。组会下载它的所有位置。

## 管道中的主题

主题可以位于管道中间：一个链接写入它，其他链接把到达的内容送到各个表。

- 向主题 **添加行** 会把这些行作为消息发送。
- **将新消息添加到表** 只读取该链接上次运行之后到达的内容。这是管道中从主题出去的
  唯一方式：每次运行都重新读取整个主题，会再次添加相同的行。
- 每个这样的链接都以自己的消费者组读取，组名为 `dataplayer-link-` 加上链接的
  id，显示在链接面板中。它的滞后可在 **消费者组** 层级看到。
- **首次运行读取** 选择首次运行从哪里开始：从主题开头，或只读之后到达的消息。
  一旦该组保存了位置，这个选择就不再起作用；要重新读取，请移动该组的位置。
- 每一块行先写入，然后再保存它的位置。如果运行在两步之间失败，下一次运行会再次
  写入这一块：消息不会丢失，偶尔会到达两次。
- **将新消息添加到新表** 连到模式而不是表时，会在首次运行时创建该表（名称、列和
  类型在其窗口中选择），之后向其中追加。如果它的列包含主题的 partition 和
  offset，在数据库允许的地方（PostgreSQL、MySQL、MariaDB、SQLite）会在它们上
  建立键，写入两次的消息只保存一次。之后被删除的表不会重新创建：要把全部内容
  读入新表，请把该组的位置移到开头。
- **按键保留最新值** 连到 Redis 数据库或文件夹时，会把每个消息键的最新值保存为
  一个独立的键，可选存活时间；详见 Redis 页面。
- 在链接面板中勾选 **跟随**，并按下管道顶部的 **跟随**，到达的内容会在几秒内传送，
  而不必等到下一次运行。管道每隔几秒查看一次，服务器重启后继续跟随；在此期间，运行和
  计划会跳过被跟随的链接。失败的链接会稍后重试，其他链接继续工作。
- Kafka 在链接读取之前删除的消息会计入运行结果。
- 如果一个组的位置一周没有写入，Kafka 会忘记它们，因此运行间隔更长的链接会按
  **首次运行读取** 的设置重新开始。

## 你自己的 Kafka

如果此服务器被允许运行容器，可以在**服务**中在本机启动一个 Kafka broker。它不需要密码——broker 会响应任何能访问到它的客户端——并且只能从本机访问。它的连接会自动为你创建。

请求示例数据即可获得一个实验室：

- `lab.orders` —— 一天内的三百条 JSON 订单，分布在三个分区中，以客户为键；
- `lab.prices` —— 每个交易对的最新价格，一个压缩主题；
- `lab.events` —— 带消息头的文本行；
- `lab.sensor` —— 以字节存储的读数，以十六进制显示；
- 组 `lab-billing`，已读取 `lab.orders` 的一部分，因此能看到它的滞后。

broker 会告诉客户端自己在哪里，而这个 broker 给出的是它在 DataPlayer 内部的地址。目录、终端和管道都能在那里访问到它；你自己电脑上的工具只能通过终端访问。

## Kafka 在这里暂时没有的功能

不提供将主题复制到另一个连接，也不提供备份。Kafka 用 MirrorMaker 复制，它是一个持续运行的服务；而它的备份是 broker 上的日志文件。重新发送每条消息两者都做不到。
