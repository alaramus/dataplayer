# RabbitMQ

RabbitMQ 代理。你可以看到它的虚拟主机、队列、流和交换器，有多少消息在等待以及由谁取走，并以行的形式读取流的消息。连接的一般用法见[连接](connections.md)页面。

## 你可以看到的内容

- 虚拟主机，以及每个虚拟主机中的队列、流和交换器
- 队列中有多少消息在等待，有多少已取走但未确认
- 谁在消费队列，以及每秒流入和流出的消息数
- 绑定关系：队列的交换器，交换器的队列
- 流的消息以行显示，最新在前，可从偏移量或某一时刻开始
- JSON 消息的字段，每个字段一列
- 流的消息或绑定可下载为文件
- 代理的报告：概览、节点、告警、连接、通道
- 仪表盘上的每秒消息数和各队列中等待的消息
- 按名称查找队列、流和交换器
- 在终端中使用已为此连接配置好的 rabbitmqadmin

## 你可以更改的内容

- 向流发送消息，逐条发送或粘贴为行
- 向交换器或队列发布一条消息
- 新建队列、流和交换器，以及删除它们
- 创建和移除绑定
- 清空队列，或用“查看消息”看一次其中的消息
- rabbitmqadmin 能更改的一切，在终端中输入

## 连接

窗口的 **连接** 页面需要填写：

- **主机** 和 **AMQP 端口**：代理接收 AMQP 的位置，默认 5672，使用 TLS 时为 5671；
- **管理地址**：管理 API 响应的位置。留空表示 `http://`、该主机和端口 15672，使用 TLS 时为 `https://`。只有启用管理插件时 RabbitMQ 才会在此响应；官方 `-management` 镜像已包含该插件；
- **用户** 和 **密码**：两者共用同一个 RabbitMQ 用户；
- **浏览器地址**：目录菜单中 **打开管理页面** 前往的地址，用于你的浏览器访问管理页面的地址与 DataPlayer 不同的情况；留空则为管理地址；
- **虚拟主机**：留空表示该用户可见的所有虚拟主机，或填写一个名称，如 `/`；
- **TLS** 和 **CA 证书**：加密连接，以及在系统不信任时签发代理证书的机构。

连接字符串 `amqp://user:password@host:5672/vhost` 会填好表单；`amqps://` 表示 TLS，路径中的 `%2F` 表示虚拟主机 `/`。

检查时先询问管理 API，再询问 AMQP。如果只有 AMQP 拒绝——用户无法打开的虚拟主机、无法访问的端口——连接仍会保存并说明原因：目录可用，流的消息不可用。

**SSH 隧道**同时承载 AMQP 和管理 API；此时主机和管理地址按 SSH 服务器所见填写。经隧道连接时请勿使用 TLS，并为**打开管理页面**填写**浏览器地址**。终端暂不经过隧道。

## 目录

- 有多个虚拟主机时，顶层列出它们；只有一个，或连接中指定了一个时，顶层是它的 **队列**、**流** 和 **交换器**。
- 队列显示其类型（classic 或 quorum）、等待的消息数、已取走但尚未确认的消息数，以及消费者数量。
- 流显示它保留的消息数以及谁在读取。
- 交换器显示其类型：direct、topic、fanout 或 headers。你的交换器在前，随后是 RabbitMQ 在每个虚拟主机中创建的交换器；没有名称的默认交换器显示为 **（默认）**。
- 这些数字来自 RabbitMQ 每隔几秒的测量，因此可能略有滞后。
- 每一层按名称显示前五百个。

## 队列和交换器

队列会保存消息，直到消费者将其取走，然后忘记它。因此不显示队列的消息：读取它们就等于取走它们。

- 队列以其绑定打开：路由到它的交换器、路由键和参数。每个队列都以自己的名称绑定到默认交换器。
- 交换器以其路由目标打开：队列或交换器、路由键和参数。

## 流的消息

流在保留期内保存消息，就像日志一样，任何人都可以从任意位置读取，而不会取走任何东西。

- 每条消息一行：偏移量、时间、到达时经过的交换器和路由键、内容类型、消息头、其他属性和消息体。
- 当消息体是 JSON 对象时，每个字段也会成为一列，名称为 `body.` 加字段名。字段取自最新的两百条消息。
- 不是文本的消息体以十六进制显示。
- 最新在前。按 **offset** 排序可从最旧的开始；其他列不能排序。
- **timestamp** 是发送方写在消息上的时间，未写时为空。按某一时刻“起”过滤时，从流本身收到该时刻的位置开始读取，精确到一批消息。
- 按 **offset** 过滤可选择读取的起点和终点。
- 其他列上的过滤会在已读取的消息中查找，每页最多十万条。
- 一页最多从末尾向前深入一万条消息。要看更早的消息，请按偏移量或时间过滤。
- 读取流不会从中取走任何东西，也不会移动任何人的位置。

## 详情面板

选择一个队列、流或交换器，然后在目录菜单中选择 **详情**。

- 队列：类型、状态、等待和未确认的消息、每秒流入和流出的消息、节点和策略、每个消费者及其通道和预取数，以及创建时的参数。
- 流：消息数、段数、每秒流入的消息、最早保留的消息何时到达、领导者和成员、消费者和参数。
- 交换器：类型、是否在重启后保留、无人使用时是否删除、是否为内部交换器，以及每秒流入和流出的消息。

## 向流发送消息

- 流的行上方的 **+** 会添加一条消息。按需填写：所有内容都可以留空。消息经由默认交换器发送，路由键为流的名称。
- **body** 是文本；`0x` 加十六进制数字会作为这些字节发送。留空并填写 `body.` 字段，则发送由这些字段组成的 JSON 对象。
- **headers** 是 JSON 对象，例如 `{"source": "manual"}`；**properties** 是由 AMQP 定义的属性组成的 JSON 对象：`message_id`、`correlation_id`、`reply_to`、`priority`、`expiration`、`type`、`app_id`、`delivery_mode`。
- **timestamp** 留空则不发送时间。
- 粘贴到流中的行会作为消息发送。如果有一个值无法读取，则什么都不发送，并指出该单元格。
- 新行在页面重新读取前没有偏移量：偏移量由流给出。

## 更改队列、流和交换器

勾选一个队列、流或交换器，或在其层级上不勾选任何内容，然后打开目录菜单：

- **新建队列**、**新建流**、**新建交换器** —— 各自在自己的层级上。队列为 classic 或 quorum；流按时长（如 `7D`）和大小保留消息；参数为每行一个 `名称=值`，例如 `x-max-length=10000`。
- **发布** —— 带路由键向交换器发布消息，或向队列发布。交换器未路由到任何队列的消息会丢失，窗口会提示。
- **绑定** —— 从交换器到勾选的队列，或从勾选的交换器到队列或交换器，带路由键。**解除绑定** 从勾选节点的绑定中选择一个。
- **清空** —— 队列中所有就绪消息都会删除；已被消费者取出但尚未确认的消息仍由其持有。
- **删除** —— 窗口会说明将删除多少消息和绑定。RabbitMQ 自带的交换器不会被删除。

## 查看消息

打开队列时不会显示其消息：读取它们就等于取走它们。**查看消息** 最多取出一百条，立即放回，并在标签页中打开所读取的内容。

- 每条消息都会被标记为 **重新投递**。quorum 队列会将这次查看计入投递上限，超过后消息会进入死信或被丢弃，消费者也可能以乱序收到消息。窗口会在查看前询问。
- 标签页显示的是查看时的样子。翻页不会再次读取队列；要重新查看，请再次执行。
- 查看结果会在 DataPlayer 运行期间保留，并在最后一次打开后保留一段时间。

## “代理”部分

目录顶部的 **代理** 汇集了代理关于自身的信息：

- **概览** —— 版本，连接、通道、队列、交换器和消费者的数量，就绪和未确认的消息数，以及每秒流入和流出的消息数；
- **节点** —— 每个节点的内存及其上限、剩余磁盘及其下限、文件描述符和运行时间；
- **告警** —— 内存或磁盘不足的节点。告警期间 RabbitMQ 会阻塞所有发布者；一切正常时报告为空；
- **连接** 和 **通道** —— 每个客户端及其用户和虚拟主机、通道、消费者、预取数以及已取走未确认的消息；
- **策略** —— 每条策略匹配什么以及设置什么。

概览、告警和连接每十秒刷新一次。长列表显示前五百项并会说明。

## 仪表盘和搜索

- **RabbitMQ 代理** 仪表盘绘制每秒消息数、每个队列中等待的消息、已取走未确认的消息、连接和告警，覆盖按名称排序的前一百个队列。
- 页眉中的搜索可在连接可见的每个虚拟主机中按名称查找队列、流和交换器。

## 在管道中

RabbitMQ 可以像 Kafka 主题一样位于管道中间：一个链接把行发送进去，其他链接把到达的内容送入表中。

- 向交换器、队列或流 **添加行** 会把每一行作为一条消息发送。每个不属于消息本身的列都会以其名称成为 JSON 消息体中的一个字段，因此表中的一行或一笔 Binance 成交会以 `{"price": …, "qty": …}` 的形式到达；同名的列会自动配对。发送到交换器时，请将某列与 **routing_key** 配对：没有该列的行会发往交换器处理空键的地方。
- 从流 **将新消息添加到表** 只读取自链接上次运行以来到达的内容。停止的位置由 DataPlayer 按偏移量保存。**将新消息添加到新表** 会在所建表上以偏移量建键，因此写入两次的消息只保留一次。
- 同样的链接从队列读取时，会像任何消费者一样取走等待中的消息：每批消息只有在写入后才会确认。如果运行在两者之间失败，这批消息会回到队列并被再次取走，并标记为重新投递。队列的其他消费者会与链接分享消息；若要让链接获得全部消息，请改从该队列的交换器画出链接。
- 从**交换器**读取时，链接通过专属队列 `dataplayer-link-…` 读取，每次运行都会创建或找到它，并按链接的**绑定键**绑定：留空时 topic 交换器为 `#`，即全部消息；fanout 和 headers 交换器不需要键。队列在首次运行时创建，因此首次运行读不到内容，之后链接会收到交换器路由的消息。修改键后从下一次运行起生效。该队列像其他队列一样显示在目录中；删除链接不会删除它，它在一周无人读取后自行消失，期间最多保留一百万条消息。连接的用户需要对该队列的 configure、write 和 read 权限，以及对交换器的 read 权限。
- 队列的列是消息本身的列；写入已存在的表时，表中其他每一列还对应 JSON 消息体中的同名字段：`price` 列取消息体的 `price`，消息中没有时为空，因此经 RabbitMQ 发送的行会自动回到原来的列。只取顶层字段；新表只得到消息本身的列。**首次运行读取** 对队列没有意义：它总是取走正在等待的消息。
- 开启的流水线会在几秒内送走新到达的内容，无论来自流还是队列，如同来自主题。

## 下载

在流上 **下载** 会保存其页面将显示的消息，按其过滤条件和顺序，最多一万条。队列或交换器下载的是其绑定。

## rabbitmqadmin

RabbitMQ 连接上的 **终端** 会打开 bash 和 `rabbitmqadmin`——RabbitMQ 自带的管理 API 命令行客户端，已指向此连接：地址、用户、密码和虚拟主机。按 Tab 可补全命令。试试：

- `rabbitmqadmin show overview` —— 代理概况
- `rabbitmqadmin list queues` —— 所有队列及其计数
- `rabbitmqadmin list exchanges` —— 交换器
- `rabbitmqadmin -V 名称 list queues` —— 另一个虚拟主机

它可以声明、删除和清空队列与交换器，发布和获取消息，导出定义；它所做的更改会立即作用于代理。终端运行在 DataPlayer 服务器上的容器中，因此该服务器需要被允许启动容器，并且从那里能访问管理地址。

## 你自己的 RabbitMQ

如果此服务器可以运行容器，**服务** 可以在本机启动一个 RabbitMQ 代理。其用户为 `dataplayer`，若你不指定密码，会为你生成一个；连接会自动创建。

请求示例数据即可获得一个实验环境：

- `lab.orders` —— 一个 topic 交换器，路由 `orders.new` 和 `orders.paid`；
- `lab.billing` —— 绑定到 `orders.#` 的 classic 队列，有六十个订单在等待，被拒绝的消息进入 `lab.dead-letter`；
- `lab.shipping` —— 绑定到 `orders.paid` 的 quorum 队列，因此只包含已支付的订单；
- `lab.dead-letter` 和 `lab.dead` —— 一个 fanout 交换器及其后的队列；
- `lab.alerts` 和 `lab.alerts.critical` —— 一个 headers 交换器，以及只接收 `level` 为 `critical` 的告警的队列；
- `lab.trades` —— 一个流，包含一天内的三百笔 JSON 交易和几条以字节存储的传感器读数，以十六进制显示。

实验环境中没有消费者，因此所有计数都保持原样。

服务行会显示其 AMQP 端口和管理 API 的端口，并附有管理页面的链接。连接菜单中的 **打开管理页面** 会打开同一页面。DataPlayer 本身通过容器名称访问代理，因此两者在本机上都可用。
