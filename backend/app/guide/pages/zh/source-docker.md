# Docker

另一台机器上的 Docker 守护进程，通过你的某个 SSH 连接或带 TLS 的 TCP 访问。你可以看到它的容器、镜像、卷和网络，守护进程对每一项的说明，容器的日志和进程，以及守护进程自身的报告。连接的一般说明见[连接](connections.md)页面。

## 你可以看到的内容

- 按 Compose 项目分组的容器，无论是否在运行
- 镜像、卷和网络，以及使用它们的容器
- 守护进程对其中任意一项的说明，以 JSON 树显示
- 一眼看清容器，机密内容在要求显示前隐藏
- 实时写入的容器日志，以及其中运行的进程
- 镜像的层以及创建这些层的指令
- 引擎：版本、驱动、CPU、内存、磁盘占用、近期事件
- 仪表板上运行中容器的 CPU、内存、网络和磁盘

## 你可以更改的内容

- 启动、停止、重启、暂停、取消暂停或强制终止容器
- 一次操作 Compose 项目的所有容器
- 删除容器、镜像、卷和网络
- 清理已停止的容器以及未使用的镜像、卷和网络
- 新建卷和网络
- 拉取公共镜像，将容器提交为镜像
- 在终端中打开运行中容器内的 shell
- 将数据库的容器作为独立连接打开

## 连接

**连接方式** 决定如何访问守护进程：**通过 SSH 的套接字** 或 **带 TLS 的 TCP**（见下文）。使用套接字时，先为守护进程所在的机器创建一个 **SSH 连接**，然后**连接**页面会要求填写：

- **SSH 连接**：你的某个 SSH 连接。其账户必须能使用守护进程的套接字——在大多数机器上，它属于 `docker` 组；
- **套接字**：守护进程在该机器上监听的位置。Docker 为 `/var/run/docker.sock`，无 root 的 Docker 为 `/run/user/<uid>/docker.sock`。**Podman** 卡片会填入 `/run/podman/podman.sock`；无 root 的 Podman 使用 `/run/user/<uid>/podman/podman.sock`，且其套接字必须已开启（`systemctl --user enable --now podman.socket`）。

套接字通过 SSH 连接转发，就像通过 SSH 隧道访问数据库一样；SSH 服务器必须允许这样做（`AllowStreamLocalForwarding`，默认开启）。如果检查提示套接字无法打开，说明以下三者之一有问题，而 OpenSSH 不会说明是哪一个：该路径上没有程序在监听、账户无权使用它，或转发已关闭。

守护进程必须支持 API 1.41 或更新版本（Docker 20.10 及以后）。

运行 DataPlayer 本身的机器上的 Docker 守护进程永远不会提供：掌握该套接字的人就掌握了这台机器。

## 通过带 TLS 的 TCP

在 TCP 上以双向 TLS 监听的守护进程（`dockerd --tlsverify`，通常在 2376 端口）无需 SSH 即可访问。表单要求填写：

- **主机** 和 **端口**：主机名须与守护进程证书中的名称一致；
- **CA 证书**：`ca.pem`，签发守护进程证书的机构；
- **客户端证书** 和 **客户端密钥**：守护进程接受的 `cert.pem` 和 `key.pem`。密钥不能加密。

请完整粘贴每个文件，包括 `-----BEGIN` 行。除非端口只能从另一个网络内部访问，否则 **SSH 隧道** 保持 **直接连接**；使用隧道时，主机是 SSH 服务器访问它所用的名称。

不使用 TLS 的 TCP 守护进程（2375 端口）会被拒绝，检查也会说明原因：能连到该端口的人就掌控了这台机器。检查还会指出失败的环节：证书不是由该 CA 签发、证书不是为该主机签发，或守护进程不接受该客户端证书。

## 目录

- **系统**包含守护进程的报告，见下文。
- **容器**中每个 Compose 项目一个文件夹，按 Compose 写入的标签命名，其余容器在**独立容器**中。每个容器用一个词显示其状态——运行、健康、不健康、启动中、已暂停、重启中、已停止、失败、已创建或已死亡——旁边是守护进程自己的状态、镜像、Compose 服务和已发布端口。
- **镜像**按 id 列出每个镜像，无论是否有标签，并显示大小以及使用它的容器数。
- **卷**按名称列出每个卷；**网络**列出每个网络，Docker 自带的三个排在最前，每个标记为内置、Compose 或用户。
- 这些文件夹也都可以作为表格打开，可按任意列筛选和排序。同一类超过一万个时不再列出。

## 节点如何打开

- 容器的**检查**以**概览**打开：状态、镜像、创建与启动时间或退出方式、重启策略和次数、命令、健康检查及其最近结果、已发布端口、网络及地址、挂载、环境变量、标签和资源上限。若容器重启超过三次或因内存不足被终止，会有一条提示。镜像、卷、网络和 Compose 项目都是链接，可在目录中显示它们。
- **以 JSON 显示**把同一标签页切换为守护进程的说明（JSON 树），**概览**再切换回来。镜像、卷或网络以 JSON 树打开。
- 名称中含有 PASSWORD、PASSWD、SECRET、TOKEN、KEY、CREDENTIAL 或 PRIVATE 的变量显示为圆点，按下其眼睛图标后才显示，显示后才能复制。这只是防止一瞥，而非防止阅读：JSON 中会完整显示，与你共享此连接的任何人都能看到容器的环境变量。
- 容器内：**日志**——每行的时间、流（stdout 或 stderr）和文本，最新在前，最多回溯一万行，单行在 16 KB 处截断——以及**进程**，即当前在其中运行的内容。已停止的容器没有进程。
- 镜像内：**历史**，即它的层。
- 卷或网络内：**容器**，即使用它的容器。

## “系统”部分

- **引擎**：守护进程的版本、操作系统、内核、驱动、CPU、内存以及容器和镜像数量，使用守护进程自己的字段名。镜像仓库镜像和代理不显示：其中可能含有密码。
- **磁盘占用**：每个镜像、容器、卷和构建缓存条目的大小，以及删除它是否能释放空间。守护进程需要测量每个卷才能回答，因此可能较慢。
- **事件**：过去一小时内发生的事，最新在前。

## 被拒绝时

- SSH 连接或套接字的拒绝会使整个连接停止，每个页面都会说明原因。
- 位于授权插件或过滤代理之后的守护进程可能拒绝单个请求：此时会显示 **Docker 服务器不允许此操作**。

## 更改

选择一个容器、一个 Compose 项目文件夹或一个节点，然后打开目录菜单。容器的生命周期操作需要写权限；删除、清理、拉取、提交以及新建卷和网络需要结构权限。

- **启动**、**停止**、**重启**、**暂停**、**取消暂停**和**强制终止**作用于所选容器，或所选 Compose 项目的全部容器。每项操作都会先列出将要做什么，以及哪些容器已处于该状态。停止和重启可以在终止前等待若干秒；强制终止会发送你选择的信号。
- **删除容器**在未勾选**强制**时不会删除正在运行的容器，并可同时删除其匿名卷。**删除镜像**会列出使用它的容器；**删除卷**不会删除被挂载的卷；**删除网络**不会删除仍有容器的网络，也不会删除 Docker 自带的三个网络。
- 在**容器**、**镜像**、**卷**和**网络**中，清理会列出将被删除的内容，镜像还会显示释放的空间。守护进程删除的是点击时未被使用的对象，因此期间变为未使用的也会被删除。
- **新建卷**和**新建网络**位于**卷**和**网络**中。
- **镜像**中的**拉取镜像**和容器上的**提交为镜像**会作为任务在**活动**中运行。只能拉取公共镜像：需要登录的仓库不受支持。

## 容器内的终端

选择一个正在运行的容器，在目录菜单中选择**终端**。选择 shell——几乎所有镜像都有 `/bin/sh`，部分镜像有 `/bin/bash` 和 `/bin/ash`——以及是否以 root 而非镜像用户身份运行。它会在窗口底部的**终端**中以容器名称打开，关闭时结束。只有连接的所有者才能打开：与你共享该连接的人不能。如果容器中没有所选的 shell，会有提示；请换一个 shell 重新打开。

## 实时更新的日志和层级

容器的**日志**打开时，新行会随容器输出出现，最多每两秒一次。你所在的目录层级在守护进程改变它时会自动重新读取：容器停止、镜像被拉取、卷被删除——无论是通过 DataPlayer 还是其他人。

## 仪表板上的指标

为该连接开启指标采集，然后在仪表板中添加 **Docker 容器** 布局。每次轮询按名称
测量最多五十个运行中的容器：CPU（100% 表示一个 CPU 完全占满，因此可能超过
100%）、不含系统可回收缓存的内存、每秒的网络和磁盘流量，以及各自的进程数。它还
统计运行、暂停和停止的容器；**未采集的容器** 统计超出五十个的运行中容器。一次
轮询约需一秒：守护进程会对每个容器测量两次以得出 CPU 使用率。

## 搜索

目录中的搜索和全局搜索可按名称找到容器、Compose 项目、按任一标签找到镜像，以及
卷和网络。在某个文件夹内，搜索只在该文件夹中进行。

## 将数据库的容器作为连接

选择一个 PostgreSQL、MySQL、MariaDB、Redis、MongoDB 或 ClickHouse 的容器，然后
选择 **作为连接打开**。会打开一个根据该容器填好的新连接表单：

- 同一个 SSH 连接，作为它的 SSH 隧道；
- `127.0.0.1` 上发布的端口，否则为容器自己的地址；
- 容器启动时使用的用户、密码和数据库。

检查后保存。镜像按其在 Docker Hub 上的名称识别，例如 `postgres` 或 `mariadb`；
其他仓库的镜像无法识别。官方 Redis 镜像通过命令行获取密码，因此需要你自己填写。
只有 Docker 连接的所有者可以这样做，因为表单中带有容器的密码。

## Docker 在这里还没有的功能

- 私有仓库，以及创建或运行新容器
