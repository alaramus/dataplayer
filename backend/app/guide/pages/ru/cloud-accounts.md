# Облачные учётные записи

Облачная учётная запись — это то, через что подключение обращается к облаку от
вашего имени: чтобы получить токен для входа в базу данных или прочитать пароль
из хранилища секретов. Она ваша, как SSH-ключ: подключение её называет, а тот,
с кем вы поделились подключением, пользуется ею, не видя её. Учётные записи
хранятся в **Настройках**, в разделе **Облачные учётные записи**; на странице
**Параметры** окна подключения тоже есть кнопка **Новая учётная запись**.

## Виды

- **Amazon Web Services**: **Ключ доступа** и **Секретный ключ**, а для
  временных учётных данных — **Токен сеанса**. Может принимать роль
  (**Принимаемая роль**) — её ARN, **Внешний ID**, имя и длительность сеанса.
- **Google Cloud**: файл **Ключа сервисного аккаунта** в JSON. Может
  действовать от имени другого сервисного аккаунта, если тот это разрешает.
- **Microsoft Azure**: **Субъект-служба** — клиент (tenant), ID клиента и
  секрет клиента.
- **HashiCorp Vault**: его **Адрес**, при необходимости пространство имён и
  сертификат CA, а также **Токен** или Role ID и Secret ID для **AppRole**.

Секреты хранятся зашифрованными и больше не показываются. **Проверить** делает
самый дешёвый безвредный вызов, который позволяет учётная запись, и говорит,
кто вошёл.

## Собственное удостоверение сервера

Учётная запись может входить и от имени машины, на которой работает
DataPlayer: цепочка учётных данных AWS по умолчанию, Application Default
Credentials Google, управляемое удостоверение Azure. Позаимствовать такое
удостоверение мог бы кто угодно, поэтому оно предлагается, только если это
разрешает установка, и только суперпользователю.

## Что с ней делает подключение

Токен выдаётся на каждое новое соединение и хранится только в памяти до
момента незадолго до истечения; ничего выданного не сохраняется. На странице
каждого источника сказано, каким его способам входа нужна учётная запись:

- PostgreSQL и MySQL: AWS IAM (RDS), Google Cloud IAM (Cloud SQL), Microsoft
  Entra, хранилище секретов, динамические учётные данные Vault.
- Redis: AWS IAM (ElastiCache, MemoryDB), Microsoft Entra.
- MongoDB: AWS IAM (MONGODB-AWS), хранилище секретов.
- Kafka: AWS IAM (MSK).
- S3: учётная запись AWS вместо ключа.

**Хранилище секретов** называет секрет там, где он хранится: в AWS — именем
или ARN; в Google — как `projects/P/secrets/S` или одним именем в проекте файла
ключа; в Azure — как `VAULT/NAME`; в Vault — как `MOUNT/PATH`. Секрет в JSON
читается по ключам `password` и `username`, которые можно переименовать; любой
другой секрет — это сам пароль.

Серверу, который проверяет пароли через LDAP, PAM, RADIUS или Active
Directory, учётная запись не нужна: для DataPlayer это выглядит как пароль.

## Ограничения

- Учётная запись сохраняет свой вид; для другого облака создайте новую.
- Учётную запись, которую использует подключение, нельзя удалить; отказ
  называет эти подключения.
- Токен, истёкший во время долгого бэкапа, его не останавливает: открытое им
  соединение остаётся рабочим.
- Инструменты Kafka в терминале пока не умеют входить через AWS IAM или OIDC.
