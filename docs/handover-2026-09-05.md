## What was built

**Declared references (D106–D109)** — the old application's "external
reference". A row of this application's own between two columns no source calls
related, including across two connections and two kinds of source. Both ends
navigable, private to its author, visible only while both ends are readable,
checked against both sources when made and again when followed. Home:
[sources/declared.md](architecture/sources/declared.md).

Following one may land in another connection, which the answer now names
(D108). The file source gained equality lookup so a reference into a CSV
actually resolves (D109) — `eq` and nothing else, applied where the rows are
read, with row handles carrying the row's real position in the file.

**Arriving references (D110)** — the way back. A source says which foreign keys
land on a relation (a capability of its own, asked once per relation), and
following one is the same call with `direction: "incoming"`. The name of an
arriving key is a handle the source issues, because a partitioned table repeats
its constraint on every partition and three menu entries would otherwise open
the first of them. Home: [sources/relations.md](architecture/sources/relations.md).

**The row view (D111)** — one row read downwards, over the page the grid is
already on, walked with Previous/Next across page boundaries, with both
directions of key navigation per column. Home: [grid.md](architecture/grid.md).

Specs for all three are in [the index](superpowers/specs/README.md), dated
today. The roadmap closed phases 1.6, 1.7 and 1.8.

## Open: buttons that do nothing

**This is the first thing to pick up.**

A panel's icon is drawn as a button whenever its look carries an `iconTooltip`
(`WorkspaceLeaf.vue`, `WorkspaceFloatingPanel.vue`), and pressing it calls
`onIconClick` in `WorkspacePage.vue`. That function handles only some kinds.
Fixed today: `rows`, `content`, `structure`, `summary`, `record` — all of them
reveal their node in the catalog, and their tooltips say "Show in catalog".

Still dead — a tooltip, a button, and nothing on press:

| Panel kind | Its tooltip today | The question to answer |
| --- | --- | --- |
| `chart` | `<connection> · Chart` | It holds a `request` with a `node_id`; reveal that? |
| `relationships` | `<n> tables · <connection>` | Several nodes, so which — or open the connection's catalog? |
| `query` | the connection's name, or that it is gone | A console has no node; the catalog of its connection? |
| `result` | `A captured result` | A captured result has no node at all |

Two ways out, and the choice is the point: either every one of them gets an
action, or the look gains a way to say "this icon is not a button" so the
header stops drawing one. The second is the honest fix for `result`, which has
nowhere to go.

## Deliberately left out, with reasons

- **Editing in the row view.** That is the grid's cell editor and its rules
  about what a source accepts; a second editing surface is a second set of them.
- **A sheet strip on a followed row.** Following a reference carries the node,
  not its container, so a workbook sheet arrived at by a key shows no siblings.
  Closing it means the answer carrying a path rather than a target.
- **A count beside each arriving key.** One query per key against a relation
  nobody has opened; the answer is one click away.
- **Composite declared references.** One column at each end until something
  asks for more.
