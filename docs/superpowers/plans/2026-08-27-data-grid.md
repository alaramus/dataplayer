# Data Exploration Grid Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a read-only data exploration grid with source-declared filters, ordered multi-sort, explicit paging, persistent column layout, spreadsheet selection and lossless copying.

**Architecture:** The backend returns lossless text cells plus a semantic, per-column capability contract. The frontend owns controlled grid state in `features/grid`, uses TanStack Table v9 only as a headless interaction engine, and sends every filter, sort and page operation to the source through Vue Query.

**Tech Stack:** Python 3.12, FastAPI, Pydantic 2, psycopg 3, Vue 3, TypeScript, Quasar 2, TanStack Vue Query 5, TanStack Table 9.2.3, Zod 4, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-27-data-grid-design.md`

## Global Constraints

- The first release is read-only: no update, insert or delete endpoint and no editable cell state.
- Filters are a flat `AND` list. Do not add `OR`, groups or raw SQL.
- Rows stay on HTTP `POST /connectors/{id}/fetch`; do not add polling or a WebSocket fetch path.
- Page sizes are exactly `50`, `100`, `250`, `500`; the default is `100`; changing query state resets to page zero.
- Every cell crossing the API boundary is `string | null`; never parse a database number into a JavaScript number for display or copying.
- Sorting, filtering and pagination are always server-side. Do not register client row models for them in TanStack Table.
- Persist column layout and per-relation filters/sort; persist page size globally; never persist page number, selection or open editors.
- Pinning is left-only. Range selection never crosses the currently loaded page.
- Source files, comments, tests and UI strings are English. Only this plan and its design spec may be Russian or mixed working notes.
- Never edit `frontend/src/client`; run `bash scripts/generate-client.sh` after the backend schemas settle.
- Use shared UI wrappers for appearance-bearing Quasar components and named layer variables for every `z-index`.
- Follow failing test -> implementation -> passing test -> commit for every task.

```python
_ORDERED = frozenset({"number", "string", "boolean", "datetime", "uuid", "enum"})
_COMPARED = frozenset({"number", "string", "datetime"})
_EQUAL = frozenset({"number", "string", "datetime", "boolean", "uuid", "enum"})


def column_capabilities(type_: ColumnType) -> tuple[bool, list[FilterOp]]:
    operators: list[FilterOp] = []
    if type_.category in _EQUAL:
        operators.extend(["eq", "ne", "in"])
    if type_.category in _COMPARED:
        operators.extend(["gt", "gte", "lt", "lte"])
    if type_.category == "string":
        operators.extend(["contains", "starts_with"])
    operators.extend(["is_null", "is_not_null"])
    return type_.category in _ORDERED, operators
```

- [ ] **Step 3: Replace the filter model with a discriminated union**

```python
ScalarFilterOp = Literal["eq", "ne", "gt", "gte", "lt", "lte", "contains", "starts_with"]


class ScalarFilter(BaseModel):
    model_config = ConfigDict(extra="forbid")
    column: str
    op: ScalarFilterOp
    value: str


class InFilter(BaseModel):
    model_config = ConfigDict(extra="forbid")
    column: str
    op: Literal["in"]
    values: list[str] = Field(min_length=1)


class NullFilter(BaseModel):
    model_config = ConfigDict(extra="forbid")
    column: str
    op: Literal["is_null", "is_not_null"]


Filter = Annotated[ScalarFilter | InFilter | NullFilter, Field(discriminator="op")]
```
