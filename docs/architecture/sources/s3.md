# S3 and compatible stores

Amazon S3 and every store that speaks its API, as one more storage under the
file explorer (D150). Read [explorer.md](explorer.md) first: the catalog, the
viewers, SQL over files and search are the explorer's, and this is only the
storage under them.

Decisions here: D379, D380, D381, D382.

```
backend/app/adapters/s3/
├── options.py   the form: endpoint, region, keys, bucket, prefix, addressing, TLS
├── client.py    the boto3 client per set of options, failures reduced to kinds
├── storage.py   S3Storage: a key's path as a node id, a bucket as a folder
├── uploads.py   an object sent as one PUT or as a multipart upload
└── adapter.py   S3Adapter(Explorer), registered as `s3`
```

`boto3`, `botocore` and `s3transfer` are imported by this package and nothing
else (`.importlinter`). boto3 blocks, as a storage does (D151), so nothing goes
back to the event loop. Since 1.36 it sends and checks CRC checksums by
default, and several compatible stores refuse them: both are `when_required`.

The test server is RustFS (`rustfs` in `compose.override.yml`, a service in
CI); see D382.

## D379. A key's path is a node id, and a bucket is a folder

- **Where browsing stands.** A connection names a bucket and a folder in it,
  or no bucket: then the root lists the buckets the key may see, and a node
  id's first segment is the bucket.
- **Ids are paths.** A node id is the key below the root, judged by the one
  containment rule (`PathPlaces`). A key no such id could name again — an
  empty, `.` or `..` segment, a drive such as `C:`, a backslash — is left out
  of a listing, as SFTP leaves out a name the rule refuses. It stays in the
  bucket.
- **A folder is a common prefix** listed with `Delimiter="/"`, or the empty
  `name/` object the providers' consoles make for an empty folder. `entry`
  asks HEAD for the key and then for one key below `key/`. `has_entries`
  answers yes for every folder, as SFTP's does.
- **Reading** is a ranged GET at any offset, buffered by 256 KB because every
  range is a request. A library that opens a path gets a copy (D152), so SQL
  reads a CSV or a Parquet object as it reads one on the disk. A search by
  content reads as little as on SFTP.
- **Facts** are a size and a last-modified time; `version` is the ETag.
- **Failures are kinds.** An unknown key, a wrong secret, a refusal, a missing
  bucket, a wrong region, an archived object, a refused certificate, a timeout
  and an unreachable endpoint each become a kind and a sentence. botocore
  names the endpoint, the bucket and the key id in its messages; none of that
  reaches the caller.
- **The client is kept** per set of options, 32 at most: making one loads the
  service model.

Known deviations:

- **A listing reads every key below a prefix**, page by page, before the
  catalog counts it: a prefix holding a million keys is a thousand requests
  before the refusal.
- **An object and a prefix of one name** — `a` and `a/b` — show as the object;
  the keys below `a/` are not reachable here.

## D380. What an object store lacks is done another way or refused

- **A write is a whole object**, which is how the explorer writes anyway:
  staged, then published.
- **Writes are conditional.** Claiming a name sends `If-None-Match: *`, and
  replacing the version a document was read as sends `If-Match` with its
  ETag; a 412 is a taken name or `VersionChanged`. A store that answers 501 to
  the header is asked HEAD first, with the race that leaves.
- **Large objects go in parts.** Up to 8 MB is one PUT; above, a multipart
  upload of 8 MB parts, a part growing by 8 MB every thousand. `incoming`
  (D168) sends parts as they arrive to the key it is going to, so a transfer
  holds one part here, and an upload that is not published is aborted, so no
  parts are left to bill.
- **No rename.** A file is copied on the server and the original deleted,
  above 5 GB by a copy of parts. A folder is every key below it moved so. A
  copy within one connection is the server's too, and passes nothing through
  here.
- **Removing** deletes keys a thousand at a time; `remove_empty` deletes the
  folder's marker only while nothing else is below it.
- **Ten thousand objects** is what one move, copy or removal of a folder may
  touch; more is refused with a sentence, because each is a request.
- **What has no counterpart is missing.** No permissions, no links, and a
  folder does not become a connection of its own: its draft would carry the
  key to the browser (`ConnectFolder` left out).

Known deviations:

- **A move is not atomic.** Cut short, it leaves keys in both places.
- **A copy claims its name by asking first**, not by a condition.
- **A versioned bucket** keeps the old versions of what is deleted, and the
  confirmation does not say so; only the current version is shown.

Spec: [S3 and compatible stores as a storage of the explorer](../../decisions/2026-11-18-s3-storage-design.md)

## D381. A bucket is made and removed in the catalog

When a connection names no bucket, the root is where buckets live.

- **New folder at the root makes a bucket.** The name is held to the rules
  every provider applies — 3 to 63 lowercase letters, digits, dots and
  hyphens, a letter or a digit at each end, no `..`, not an IP address — before
  anything is sent, and it is made in the connection's region. Whether a
  bucket exists is read from the list of buckets, since HEAD answers a name no
  bucket may have with a 400.
- **Delete at the root removes a bucket** with what it holds, within the ten
  thousand objects. A versioned bucket that still keeps versions is refused:
  emptying it is a lifecycle rule's job.
- **Nothing else lives at the root.** A file there, and a rename or a copy of
  a bucket, are refused with a sentence.

Known deviations:

- **Rename and copy are offered on a bucket** and refused when chosen: the
  explorer offers actions by kind, and a bucket is a folder.

Spec: [S3 and compatible stores as a storage of the explorer](../../decisions/2026-11-18-s3-storage-design.md)

## D382. One form, a card per provider, nothing started here

- **The form** asks for an endpoint (empty for Amazon S3), a region, the access
  key and its secret, a bucket (empty for every bucket), a folder, the
  addressing and whether to verify the certificate. TLS is the endpoint's
  scheme. Auto addressing is virtual-hosted on Amazon S3 and path-style
  everywhere else.
- **An address never carries a key.** `s3://bucket/folder`, an Amazon S3 URL
  either way round — `bucket.s3.region.amazonaws.com/folder` or
  `s3.region.amazonaws.com/bucket/folder` — and a path-style URL
  `https://host:port/bucket/folder` fill the endpoint, region, bucket and
  folder. One with a user, a password or a query is refused, so a presigned
  link is not taken apart. The address shown is written back the same way.
- **Cards** (D264, D377) are the one type and the one form: Amazon S3, MinIO,
  RustFS, Cloudflare R2, Backblaze B2, Wasabi, DigitalOcean Spaces, Google Cloud
  Storage, Yandex Object Storage, VK Cloud, Selectel and Hetzner Object
  Storage. Each fills what its provider always names the same — R2's region
  `auto`, Google's and Yandex's and VK's endpoints — and says where the rest is
  found. Amazon S3 wears AWS's logo; the others are simple-icons' marks in
  their brand colours, and Selectel's was drawn from its own.
- **No service template.** MinIO stopped publishing images in 2025 and archived
  its repository in 2026, and this product starts open-source servers only.
  MinIO stays a card: connecting to a running server costs nothing.
- **The test server is RustFS**, Apache-2.0, configured by environment and
  started with no arguments, so CI runs it as a service container; the tests
  that need it skip without it except under `--require-services`.

Known deviations:

- **Sign-in is by key only**, as the hosted database cards sign in by password:
  IAM roles, instance profiles and Google service accounts are a later step.
